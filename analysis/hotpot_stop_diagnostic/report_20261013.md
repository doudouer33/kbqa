## 1. 结论

**stop 修复已生效，三个 k 的小样本平均 F1 均改善，但答案提取问题仍明显。**

- 40 道固定题目：bridge 20、comparison 20；k=1、8、15 各 40 次，合计 **120 次真实 API 推理**。
- 120/120 个 HTTP 请求明确包含 `stop=[]`，模型 ID 均为 `Qwen2.5-7B-Instruct`；120 个响应均为 HTTP 200。
- HotpotQA 官方 F1：k=1 为 **11.85%→14.74%**，k=8 为 **21.62%→30.87%**，k=15 为 **16.71%→24.42%**。
- 44 条输出包含实际换行；其中 17 条在第一个换行之后才出现 `answer is` 答案标记，说明换行后的内容现在可以正常生成。

- k=15 有 39/40 条 prompt 被进一步删除 CoT 示例；本次没有发现测试题本身被裁剪。

```json
  "model": "Qwen2.5-7B-Instruct",
  "frequency_penalty": 0,
  "logprobs": false,
  "max_tokens": 300,
  "n": 1,
  "presence_penalty": 0,
  "stop": [],
  "temperature": 0,
  "top_logprobs": null,
  "top_p": 1
}
```

完整 `messages`、返回的原始正文、usage、finish_reason 和 stop_reason 保存在 [http_events.jsonl](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/predictions/hotpot_stop_40_20261013_1050/http_events.jsonl)。该文件有 120 条 request 和 120 条 response；[diagnostics.jsonl](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/predictions/hotpot_stop_40_20261013_1050/diagnostics.jsonl) 按题将请求、响应、prompt 裁剪前后、提取输入及最终答案关联起来。

| k | 原始输出含实际换行 | `answer is` 在首个换行之后 | 原始输出含答案标记 |
| --- | --- | --- | --- |
| 1 | 16/40 | 8/40 | 15/40 |
| 8 | 14/40 | 4/40 | 19/40 |
| 15 | 16/40 | 5/40 | 17/40 |

全部 120 条原始文本已离线复核。它们以完整句子或引号结尾，没有看到首行截断或 token 上限造成的残句。但 **EOS 正常结束不保证回答了问题**：51 条有显式 `answer is` 标记，余下 69 条包含自然语言结论、直接回答或“信息不足，无法回答”等内容，不能统称为成功生成了规范最终答案。

正向证据：k=8，`5a8bbfb15542995e66a474f6`。历史 CoT 只有首句：

```text

```

```text

```

新提取器正则命中，最终为 `that they are both tennis players`，官方 F1 从 14.29%→22.22%。这同时证明换行后的生成恢复，以及短答案提取仍不够干净。见 [对应诊断记录](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/predictions/hotpot_stop_40_20261013_1050/diagnostics.jsonl:45)。

全部输出的可读复核材料见 [raw_output_review.md](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/predictions/hotpot_stop_40_20261013_1050/raw_output_review.md)。

### 4.2 答案提取：普通实体和 Yes/No

提取过程由 [AnswerExtractor.query](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/commaqa/inference/ircot.py:220) 执行。本报告的“首选提取成功率”严格定义为原有正则首次匹配成功；全文回退不算成功。

| 答案类别 | k=1 首选命中旧→新 | k=8 首选命中旧→新 | k=15 首选命中旧→新 |
| --- | --- | --- | --- |
| 普通答案，34 题 | 4/34 → 10/34 | 10/34 → 18/34 | 7/34 → 15/34 |
| Yes/No，6 题 | 0/6 → 5/6 | 0/6 → 1/6 | 1/6 → 2/6 |

**Yes/No：正则即使命中也没有输出纯 yes/no。** 例如 k=1，`5ae14def55429901ffe4ae4a`：模型完整推理后给出 `the answer is yes, both Lee Tamahori and Robert Redford work as directors.`；提取结果为 `yes, both Lee Tamahori and Robert Redford work as directors`，gold 为 `yes`，官方 F1=0。见 [记录 11](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/predictions/hotpot_stop_40_20261013_1050/diagnostics.jsonl:11)。另外也有模型判断错误或自相矛盾的 Yes/No 输出，不能把这 18 条全部归因于提取器。

**普通实体：有答案但缺少约定标记时，全文回退保留整段。** 例如 k=15，`5a89fb525542993b751ca9d6` 的原始输出已经明确包含正确实体 `Anna Clyne`，且正常结束；因为没有 `answer is`，最终答案是整段介绍，官方 F1 仅 6.56%。见 [记录 115](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/predictions/hotpot_stop_40_20261013_1050/diagnostics.jsonl:115)。

这类异常由约定格式缺失、[全文回退分支](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/commaqa/inference/ircot.py:224) 和宽泛 `(.*)` 捕获共同造成。`answer is that ...`、`answer is yes, ...` 也会把句子尾部解释一起捕获。当前样本没有观察到实际换行使首选正则漏掉已存在的 `answer is` 标记：上游先 JSON 序列化，换行已成为字面量 `\n`，因此不能简单把这里的问题诊断成“缺少 DOTALL”。

### 4.3 finish_reason 与正常 EOS

120 条原始响应均为 `finish_reason="stop"`，`stop_reason=null`；没有 `length`、异常响应或重试。`stop=[]` 禁用用户指定的字符串停止条件，模型仍可正常 EOS 结束。本次观测与正常结束一致，不能因 `finish_reason` 叫 `stop` 就认为换行 stop 仍在生效。

原代码 [_chat_response_to_legacy_dict](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/commaqa/models/gpt3generator.py:37) 只保留正文及可选 logprobs，丢弃 usage 和 finish_reason。没有将正常 EOS 判为异常的分支；原日志只是缺少这些诊断信息。本次在转换之前保留完整响应，并未改变转换函数或 EOS 行为。`stop_reason=null` 没有提供具体 EOS token ID，因此报告不宣称识别到了某个指定 EOS token。

### 4.5 Prompt 上下文裁剪，特别是 k=15

裁剪有两层，均为原有行为：

1. [read_prompt](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/commaqa/inference/prompt_reader.py:127) 初始化时受 4,000-token 预算影响，选中的 15 个 CoT 示例删除 9 个，三个 k 都先得到 6 个。日志和 [prompt_initialization.jsonl](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/predictions/hotpot_stop_40_20261013_1050/prompt_initialization.jsonl) 均记录了此事。
2. 每道题加入检索上下文后，[fit_prompt_into_given_limit](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/commaqa/inference/prompt_reader.py:197) 按 `first` 再删除示例。

| k | 完整 prompt 再次发生裁剪 | 最终 CoT 示例数量分布 | 测试题部分发生改变 |
| --- | --- | --- | --- |
| 1 | 0/40 | 6 个：40 题 | 0/40 |
| 8 | 6/40 | 6 个：34 题；5 个：6 题 | 0/40 |
| 15 | 39/40 | 6 个：1 题；5 个：19 题；4 个：19 题；3 个：1 题 | 0/40 |

例如 k=15，`5ab70f79554299110f219aa9`，本地原始完整 prompt 为 4,796 tokens，拟合后为 3,369 tokens；示例由 6 个降为 3 个。测试题与检索正文保持相同，API prompt tokens 为 3,398。

因此 **k 增大同时改变了检索数量和实际保留的 CoT 示例数量**，后续解释 k=8 与 k=15 的差异时必须考虑这一点。服务虽然支持 32,768，客户端仍沿用历史 4,000 预算；本次没有扩大预算，以保持 stop 的独立改动。

本次没有触发 [逐行删除测试题前部的兜底分支](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/commaqa/inference/prompt_reader.py:225)。静态看，该分支按 `model_length_limit` 保留正文，没有再次扣除生成预算；若未来测试题本身很长，应单独验证这一行为，不能把潜在风险写成本次已发生的截断。

### 4.6 生成完整后，后处理是否丢失内容

120/120 条 API `message.content` 与生成器返回的文本完全相等；120/120 条提取器输入经 JSON 解码后与原始文本 `.strip()` 相等。`LLMQAModel` 本次仅执行 [原有 strip 与 JSON 尝试解析](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/commaqa/execution/llm_qa_model.py:54)，没有中途截断正文。

但提取后的字符串确实存在表示污染：

| k | 最终答案含字面量 `\n` | 最终答案含字面量 `\u...` |
| --- | --- | --- |
| 1 | 8/40 | 5/40 |
| 8 | 10/40 | 2/40 |
| 15 | 11/40 | 4/40 |

两列可能重叠。29 条字面量换行全部出现在首选正则失败、全文回退的结果中。路径是：

```text
原始正文含换行 / Unicode
→ participant_qa.update_state: json.dumps(answer)
→ AnswerExtractor 只移除首尾引号
→ 对仍带 JSON 转义的字符串匹配 / 回退
→ 某些非 JSON 的普通字符串无法经现有解码兜底还原
→ 最终答案保留 \n、\uXXXX、\" 等文本
```

相关位置：[JSON 序列化](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/commaqa/inference/participant_qa.py:88)、[只剥引号](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/commaqa/inference/ircot.py:220)、[解码兜底](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/commaqa/inference/ircot.py:236)。

例如 k=1，`5abcc818554299658360048b`：原始答案段是 `the 4 × 100 metre relay`，最终字符串却保留 `the 4 \u00d7 100 metre relay`；见 [记录 7](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/predictions/hotpot_stop_40_20261013_1050/diagnostics.jsonl:7)。这是后处理表示改变，不能算模型生成被截断，也不能把该题剩余误差全部归因于转义，因为 gold 同时使用 `x` 等不同表述。

评估阶段 [evaluate.answer_extractor](/media/hnu/hnu2021/dengxin/luoyichen/kbqa/evaluate.py:47) 还会在普通评分路径再次运行类似正则，官方评分路径则直接使用最终预测。这一原有差异已经保留，本报告分别呈现两套指标；没有用离线替代提取器重写预测。

### 4.7 与旧实验对照的证据边界

旧 chains 可以恢复模型正文、提取后答案和检索标题，故可以配对统计 F1 与首选正则命中率。旧响应没有 token usage、finish_reason 或实际请求 body，无法恢复其准确的停止 token 和生成预算实际使用情况。

历史配置没有显式 stop，当前生成器默认是 `["\n"]`，历史输出也存在只有开场一句的情况；这支持原先的换行 stop 怀疑。新的真实请求、跨行输出和跨行后的答案标记则直接证明本次修复生效。报告将这些直接证据与不能严格控制的历史服务差异分开处理。

## 5. 建议下一步，仅建议，尚未实施

1. **先修复答案提取与序列化边界。** 将原始字符串与 JSON 表示明确区分，正确恢复换行、Unicode 和引号；对已存在的明确答案标记提取干净短答案，覆盖 Yes/No、实体名与多行正文，并明确全文回退的失败状态。用本次保存的输出做离线回归可先验证效果，无须立即增加模型推理。针对判断错误的输出不能通过机械截取 yes/no 来掩盖。

`run.py verify` 的未定义变量也值得后续单独修复，但不属于本次 stop 的功能性改动。
