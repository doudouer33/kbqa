## 2. 正则差异与原因

原正则：

```python
r".* answer is:? (.*)\.?"
```

新正则完全采用建议方案：

```python
r"(?s).* answer is:? ([^\r\n]*)\.?"
```

Jsonnet 中的实际写法：

```json
"regex": "(?s).* answer is:? ([^\\r\\n]*)\\.?"
```

`(?s)` 允许前面的贪婪 `.*` 跨过推理中的换行，继续寻找最后一个符合既有约定的 `answer is` 标记；`[^\r\n]*` 将捕获限定在标记所在行，避免把下一行解释带入答案。贪婪策略、标记的大小写/冒号规则和末尾句点处理没有改变。未增加 Yes/No、短答案启发式或特定 qid 的修正规则。无标记时仍使用公共提取器原有 `(.*)` fallback。

Jsonnet 求值及真实提取链路测试确认反斜杠转义正确。对 **k=1～15** 使用现有 `run.py.instatiate_config()` 进行静态实例化并求值；把新正则恢复为旧正则后，候选与原配置的字典完全相等，检索数量也分别等于对应 k。没有调用 `run.py write/predict` 或覆盖旧实例化配置；求值快照保存在新结果目录。
