## 3. 旧 `unicode_escape` 为什么没有修好

旧代码先尝试 `json.loads(answer)`。如果失败，再尝试：

```python
answer = json.dumps(json.loads(answer.encode("utf-8").decode("unicode_escape")))
```

例如 `Atl\u00e9tico Mineiro` 经 `unicode_escape` 暂时还原为 `Atlético Mineiro`，但这仍然是普通短答案，没有 JSON 引号，后续 `json.loads()` 失败。整条赋值没有执行，异常被吞掉，原污染字符串仍被保存。

这个补救原本用于把被外层 JSON 转义的列表片段 `[\"1,450 miles\"]` 恢复为合法列表。正确解码外层 JSON 字符串后，原本合法的列表已自然恢复，无需该补救。继续执行它还可能把本来正确的 UTF-8 字符解成乱码，或误解释真实反斜杠。本次因此移除了这段提取后处理，没有加入替换特定字符、无条件解码或二次解码循环。

### 7.1 Atlético Mineiro：k=1、8、15，分别一条

问题：What is the colloquial name of the professional football team in which striker Frederico Chaves Guedos played?

Gold：`Rooster`。三个 k 的原始输出相同：


### 7.2 接力项目：k=1、15，分别一条

问题：In which event did Tyson Gay and Rodney Martin both represent the United States at the 2008 Beijing Olympics?

Gold：`4 x 100 metre relay`。

k=1 原始输出：

```text
Rodney Martin and Tyson Gay both represented the United States in the 4 × 100 metre relay at the 2008 Beijing Olympics. So the answer is: 4 × 100 metre relay.
```

k=15 原始输出：

```text
Tyson Gay and Rodney Martin both represented the United States in the 4 × 100 metre relay at the 2008 Beijing Olympics. So the answer is: 4 × 100 metre relay.
```

两条都恢复了真实乘号 `×`。原官方规范化不会把 `×` 换成 `x`；正确恢复后仍有 4/5 个词匹配，F1 为 0.8、EM 为 0。未按 gold 将乘号替换为字母，也未修改规范化方法。历史浮点 F1 `0.8000000000000002` 与修复后相同，表中简写为 0.8。

### 7.3 唯一额外变化：k=1 的 Peter Curtis / Scott Draper

问题：Peter Curtis and Scott Draper are both what?

Gold：`former tennis player`。原始模型输出包含一个真实换行：

```text
Scott Dennis Draper is an Australian former tennis player. There is no information provided about Peter Curtis, but based on the given context, if we are to compare Scott Draper's profession, the answer would be: tennis player.
So the answer is: tennis player.
```

旧代码去掉 JSON 引号后仍保留字面量 `\n`，整个输入在正则看来只有一行，因此首选正则能命中末尾答案，预测为 `tennis player`。

新代码正确恢复换行。原正则使用 `match()`，且 `.` 不跨换行，无法从第一行匹配到第二行的 `answer is`；既有 `match_all_on_failure=True` 随后使用 `(.*)` 捕获第一行。移除末尾句点后，新的完整预测为：

```text
Scott Dennis Draper is an Australian former tennis player. There is no information provided about Peter Curtis, but based on the given context, if we are to compare Scott Draper's profession, the answer would be: tennis player
```

官方 F1 从 0.8 降至 0.1621621621621622；仓库 F1 从 0.8 降至 0.18；EM 均保持 0。**没有增加 DOTALL、替换换行、只读最后一行或新增提取策略来维持分数。** 因此首选正则命中数从 120/120 变为 119/120；这是原正则在真实文本上的结果，不能继续声称真实文本的命中率为 100%。

## 9. 兼容性范围与剩余风险

1. **JSON 列表保留既有语义。** 提取器只对完整双引号 JSON 字符串解一层，不把以 `[` 开始的数组、对象、数字、布尔或 null 改成别的类型。最终 `QuestionSearchBase` 仍按原方式将合法列表文本转为 `list`。Direct QA 没有经过提取器，行为不变。
2. **普通原始字符串保留。** 未加 JSON 引号的 `last_answer` 和普通 `last_question` 不做 escape 解码。`last_question` 的外层引号剥离维持既有行为；本次不将它扩展为新的 JSON 协议。合法双引号 JSON 字符串处于 `last_answer` 时按现有答案存储协议解释；由于 `QuestionAnsweringStep` 只有 `str` 类型标注，没有表示来源元数据，无法额外区分“恰好长得像 JSON 字符串的原始引用文本”。本次没有为此改变公共数据结构。
3. **解码只执行一次。** 例如外层 JSON 中的 `\\u00e9` 还原为原文字面量 `\u00e9`，不会继续解为 `é`。有效转义引号、换行、反斜杠也由 JSON 规范处理；没有 Unicode 归一化。最终模块原有的合法 JSON 字符串/列表识别仍保留，不能把它误称为本次新增的通用解码。
4. **历史 malformed-list 补救停止。** 如果原文自身包含无效的 `[\"…\"]` 而不是外层 JSON 序列化造成的转义，本次会保留原文字面量，不再尝试 `unicode_escape` 修补。正常的外层 JSON 字符串包裹合法列表已由正确边界解码覆盖。依赖旧补救来猜测非规范表示的外部调用者可能有变化；本批 120 条没有此类额外变化。这是移除不安全补救的明确兼容边界。
5. **真实换行与原正则的兼容问题存在。** 本批已经出现 1 条，完整记录在第 7 节。要让这条仍提取末尾答案，需要另行改变提取行为，超出本次范围，本次没有实施。其余 114 条保持一致，包括现有 Yes/No、重复 marker 和答案后附解释的既有处理结果。
6. **已有完整测试错误未处理。** 新增测试全部通过，但全仓库“全部测试通过”的更强验收条件仍被已有客户端测试的缺失符号阻碍。本次没有修改模型调用以消除这个范围外问题。

## 10. 后续正式 500+500 实验建议

**建议后续正式实验采用本次 JSON 字符串边界修复，并将它记录为明确的答案表示处理版本变化。** 修复恢复的是模型真实字符，不保证提升分数；当前 5 条污染已全部消除，单行 ASCII、正常 Unicode、字面量反斜杠和合法列表有自动测试覆盖。

同时应保留本报告记录的限制：正确恢复换行会触发现有正则的跨行限制，因此不能保证所有旧预测均不变，也不能沿用旧的 120/120 真文本匹配率结论。如果后续要处理多行答案，应作为独立提取策略任务评估，不混入本次修复。本次工作停在最小代码修复、自动测试、离线回归与报告，未执行正式实验。
