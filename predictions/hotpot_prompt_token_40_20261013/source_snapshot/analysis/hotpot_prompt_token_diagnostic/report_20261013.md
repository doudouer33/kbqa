```text

3. End your response with exactly this format: So the answer is: <answer>.
4. The <answer> must contain only the short answer, without explanations or additional descriptions.
5. For yes/no questions, the <answer> must be exactly "yes" or "no".
```

## 8. 失败类型必须分开看

### 8.1 模型未遵循格式

2 条没有满足“单行 + 约定末尾”的核心约束：k=1 的 Peter Curtis 题输出了真实换行；k=8 的 Tetrapanax 题用小写 `so`，并在 `yes.` 后继续解释。后者原正则命中却提取成冗长文本，官方 F1=0。另有 k=1 的共同地区题重复两次最终答案标记；最后一个答案仍可正确提取，但内容冗余，严格单标记统计失败。

这些原始输出完整保存；没有删换行、截到 yes/no、修改大小写或删解释来补救。

### 8.2 提取器/序列化未正确处理输出

5 条符合尾部格式的输出，最终预测与模型的末尾短答案不一致，均是已有 Unicode 转义问题：Atlético Mineiro 在三个 k 下共 3 条，以及 `4 × 100 metre relay` 在 k=1/15 共 2 条。原 JSON 序列化把 é/× 变成转义文本，提取路径未恢复，最终预测残留字面量 `\u00e9` / `\u00d7`。

这说明**正则命中 100% 仍不等于原始字符串提取正确**。球队题同时回答了正式队名而不是 gold 的昵称 Rooster，不能把它的 0 分全部归因于转义。接力题的 gold 使用 `x`，模型使用 `×`，原官方标准还存在表述匹配差异；本轮不替换字符、不改 gold，也不估算“修好后”的分数。

### 8.3 格式正常但答案错误或不完整

120 次官方评分为 **52 次满分、30 次部分分、38 次零分**。其中 **34 次**既满足末尾语法、又与模型末尾答案一致，却官方 F1=0，属于模型作答与固定 gold 不匹配，不能归因于正则漏匹配。

18 次 Yes/No 中，17 次提取为纯 yes/no；其中 12 次正确、5 次判断错误，另 1 次因格式失败得到冗长答案。k=1/8/15 均正确 4/6；k=15 的国籍题推理自相矛盾却输出纯 no，提取器如实提取了错误答案。Muzzle 题三个 k 均输出 yes、固定官方 gold 为 no；按原标准记 0，不更改标注。

普通实体题共 102 次，官方 F1 27.46%→57.70%，EM 13.73%→39.22%。仍有实体混淆、日期/大小比较推理错误、全名缩写及表述粒度不一致。例如 Wayne Boden 相对 Wayne Clifford Boden 得到部分分；`scent hound` 相对较长 gold 得分偏低。本轮保持评分口径。

有 **9 次普通实体题**在说明信息不足后给出最终 `no`。这不是对应 Yes/No 题的正确否定答案，而是未能回答实体问题。是否受到 Yes/No 指令影响，本轮没有独立消融，不能断言。

更高 k 也可能引入同名实体干扰：Peter Curtis 被误答成共同姓氏，Diva 被当成蛾类，年龄题给出的日期和“更年轻”结论不一致。格式强化没有解决这些语义问题。部分官方满分输出的推理仍有错误或未经上下文支持的事实，答案分数不衡量全部 CoT 质量。

### 8.4 Token 预算问题

初始化裁剪 **0**，运行时裁剪 **0**，问题/检索正文改变 **0**，自动降长 **0**，`finish_reason=length` **0**。本轮上述失败均没有 Token 不足证据，不能将它们解释为预算造成的截断。
